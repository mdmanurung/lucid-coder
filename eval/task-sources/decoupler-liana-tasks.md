"not stated" means the page does not say it. "Unverified" marks a trap outcome I expect but have not run.

## Pin recommendation

**Pin decoupler v2 (`decoupler>=2`, ideally `==2.3.1`), not v1.9.2.**

- Every liana-py release from v1.7.0 on requires `decoupler>=2.0.0`. Current liana (`V2.0.0`, main) also needs Python >=3.12. liana v1.6.x is the last line that works with decoupler 1.x.
- This repo already pins `decoupler>=2` and `liana>=1.10` in `bench/target/pyproject.toml` and `bench/target-full/pyproject.toml`. The existing `tfact` task in `bench/pipelines/tasks.yaml` prompts with `dc.mt.ulm` and `dc.tl.rankby_group`.
- The LIANA tutorials call the v2 API themselves (`dc.pp.pseudobulk`, `dc.op.collectri`, `dc.mt.ulm`).
- The `dc.ds.*` loaders exist only in v2, and they turn each dataset into a one-line fixture build.

Use v1.9.2 only for a task that tests the v1 API itself (for example, "the agent must not call `dc.run_ulm` on a v2 install"). In that case, build a separate env with liana <=1.6.

**Gate on the pinned version's numbers only.** v1 and v2 give different scores and top hits on the same data (see candidates 2 and 5).

## R versions

decoupleR (Bioconductor) and LIANA R (`saezlab/liana`) mirror these workflows. I did not fetch their vignettes, so no R API names or results are recorded here. The Python v1.9.2 pages link LIANA R at `https://saezlab.github.io/liana/`.
