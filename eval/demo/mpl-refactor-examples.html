lucid-coder · before and after

MPL differential analysis, with and without the plugin

One script from the Senegal urban-rural study, src/_MPL_differential_analysis.R: a robust limma trend test on MPL-stimulated subcluster frequencies. Opus 5.5 refactored it and also wrote it fresh from a five-step spec, with no plugin (A), with lucid-coder (C), and with lucid-coder plus three learned rules (D). No run had the data, so no script was executed.

Every snippet below is air-formatted at 100 columns. In the from-scratch runs C and D ran air themselves and A happened to match it, so layout no longer separates the arms. What is left is how the code is written.

Highlighted lines are the ones each comparison is about.

Where the plugin versions go wrong

  • C changes an output column. It strips the lineage prefix from cluster, so CD4T_Th1 becomes Th1. Your original keeps the full name, so figure scripts that join on it would break.
  • A spare check. C adds a row-count stop() after a join that already has relationship = "many-to-one", so it cannot fail on its own.
  • D refuses to overwrite. It stops if the two fixed output files exist, so every rerun needs a manual delete. The rule was written for run folders, not fixed paths.
  • Over-naming. LINEAGE_PATTERN and ANNOTATION_PATTERN give a constant to a regex used twice.
  • LD413. The refactor guessed it is a "reference (control) sample". The from-scratch versions say the reason is not recorded, which is accurate.
