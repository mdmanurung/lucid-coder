lucid-coder · before and after

MPL differential analysis, with and without the plugin

One script from the Senegal urban-rural study, src/_MPL_differential_analysis.R, is a robust limma trend test on MPL-stimulated subcluster frequencies. Opus 5.5 wrote the same analysis from a five-step spec in R and in Python. A is no plugin, C is lucid-coder, and D is lucid-coder plus three learned rules. No run had the data, so no script was executed.

The plugin's rules were rewritten after three agents read the code of 17 expert repos for concise idioms and project shape. The reference repos were immgenT for R, and sound-life and aifi for Python. This page compares the scripts before and after that rewrite. All R is air-formatted, so layout is not the difference.

Highlighted lines are the ones each comparison is about.

R · checks

Six-line checks become one line

The old rules asked for stop() with a message, so every check took a block. The corpus uses stopifnot(). R's named form keeps the message on one line.

C · old rulesblock per check
C · corpus rulescolumn checks gone, one line each
D · corpus rulesalign by name, no check needed

D uses the immgenT idiom meta[rownames(L), ]. Indexing by name puts the rows in matrix order, and column_to_rownames() fails on a duplicated patient. So the alignment check has nothing left to catch.

How the expert repos use notebooks and scripts

  • Where the repo was made decides the split. The Allen Institute repos are nearly all notebooks: aifi 82, sound-life 82, IHA 286, ALTRA 163. MOCHA is 108 plain .R scripts. Hoffman's dreamlet and variancePartition repos are Rmd. immgenT computes in .R and uses Rmd only to show figures.
  • Where a split exists, it follows runtime. Long or batch jobs are scripts run by .sh or SLURM wrappers. Judgement steps such as QC review, annotation and figures are numbered notebooks. MM keeps 17 .py files in jupytext format, so they also open as notebooks.
  • Notebooks never call notebooks. No repo uses %run, papermill or Rmd params. Notebooks reach shared code with source(), or with sys.path plus an import. One driver, GTestimate's run_analysis.R, renders the Rmds in order.
  • Steps hand off through files named after the step. The formats are CSV, .rds, h5ad, or .obs as parquet. aifi and sound-life go through a data platform by UUID.
  • Variants are copied notebooks (10a-10g, 05a/b/c), and the copies drift. In sound-life one copy lost a filter. The plugin asks for one parameter and one loop instead.

The new core rule says compute steps write files, and each figure or table has its own script or notebook that reads them. Batch jobs are scripts. Judgement steps may be notebooks, with markdown headings in place of banner comments.

Check before trusting the plugin versions

  • R arm C changes an output column again. It strips the lineage prefix from cluster, so CD4T_Th1 becomes Th1. Your figure scripts join on the full name. D keeps it.
  • Python arm D departs from the spec. A patient with no cells in a whole lineage gets a missing value for that lineage's subclusters, not 0. The script says so in a comment. It is arguably more correct, but it is not what was asked.
  • R arm C has one line over 100 columns. It is a named stopifnot(), so air format --check fails on C. D passes.
  • Python arm C adds a sys.path line it does not need. Python already puts the script's folder on the path.
  • One run per arm. These are demos, not the eval grid, so a single run can be lucky or unlucky.
