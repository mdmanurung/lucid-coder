MPL differential analysis, with and without the plugin

One script from the Senegal urban-rural study, src/_MPL_differential_analysis.R: a robust limma trend test on MPL-stimulated subcluster frequencies. Opus 5.5 rewrote it under the same prompt with no plugin (A), with lucid-coder (C), and with lucid-coder plus three learned rules (D). No run had the data, so no script was executed.

Refactor · example 1

Design rows matched to matrix columns by position

lmFit() pairs the design rows with the matrix columns by position. If the two orders differ, every patient gets another patient's group, age and sex, and the script still runs.

A explains the risk; C makes it fail loudly. C also selects the coefficient by name, so adding a term to the formula cannot move coef = 2 onto age. The name group.L is correct: weightedcontrasts.R names its columns .L, .Q, .C.

relationship = "many-to-one" turns a duplicated metadata row into an error instead of a silent doubling of that patient's cells. Both A and the plugin arms named the coefficients and aligned the design with match() here, so those are model defaults, not plugin effects.

Rule change · example 4

A new line after every pipe

D still packed short chains onto one line. A new rule in rules/r.md now asks for one step per line, even for two steps. The rerun of D has no line with a step after |>.

Check before trusting the plugin versions

  • LD413. The refactor calls it a "reference (control) sample". That is a guess; the other scripts only drop it. The from-scratch versions say the reason is not recorded.
  • Spare checks. D after the pipe rule adds a row-count check after a join that already has relationship = "many-to-one", which cannot fail on its own. The house style counts that as outside the budget.
  • Length. C from scratch is twice as long as A. Part of that is a Notes block explaining why clean_names() was not used.
  • Formatting. No version passes air format --check; all differ from air in call layout.
