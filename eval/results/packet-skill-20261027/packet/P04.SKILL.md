# pseudobulk-de

## Why This Exists

Testing single cells as if they were independent replicates (a Wilcoxon test per cell, for
example) treats hundreds of cells from one donor as hundreds of samples. Many genes then come out
falsely significant because variation between donors is ignored (pseudoreplication). This skill
uses the donor as the replication unit: it sums each donor's cells into one pseudobulk library and
fits a count model across donors. Pseudobulk methods of this kind perform best in benchmarks
(Squair et al. 2021; Crowell et al. 2020).

## Core Capabilities

- Aggregates raw UMI counts to one pseudobulk library per donor (sum over cells).
- Drops donors with too few cells and filters genes with `edgeR::filterByExpr`, reporting what
  each filter removed.
- Normalises with TMM, then fits an edgeR negative binomial GLM with quasi-likelihood F-tests,
  design `~ condition`, with `healthy` as the reference level.
- Reports `log2_fc` (disease vs healthy), `p_value`, and Benjamini-Hochberg `q_value` over all
  tested genes.
- Writes a reviewer-facing `report.md` with a captioned figure that shows each donor as a point.
- Refuses to write into an output path that already exists.

## Input Formats

`--input <dir>` must contain two tab-separated files:

| File | Layout |
|---|---|
| `counts.tsv` | Raw UMI counts, genes × cells. First column `gene`; every other column is one cell, headed by its cell ID. Integer counts, not normalised. |
| `cells.tsv` | One row per cell: `cell_id` (matches the count column names), `donor_id`, `condition` (`healthy` or `disease`). |

Every count column must have a row in `cells.tsv`, and each donor must belong to one condition;
the script stops otherwise. Any other `condition` value is an error.

## Workflow

1. Parse `--input` and `--output`; stop if either is missing or the output path exists.
2. Read the counts and cell metadata; align the metadata to the count columns by cell ID.
3. Count cells per donor; drop donors with fewer than `min_cells_per_donor` (10) cells.
4. Sum raw counts over each donor's cells → genes × donors pseudobulk matrix.
5. Keep genes that pass `edgeR::filterByExpr(group = condition)`.
6. Compute TMM normalisation factors, then `glmQLFit` with design `~ condition`, then `glmQLFTest`
   on the coefficient `conditiondisease`.
7. Apply BH adjustment over the tested genes; genes removed by the filter keep a row with `NA`.
8. Write `de.tsv`, the figure and its source data, `report.md`, `result.json` and the
   reproducibility files.

Parameters a user may change (`condition_levels`, `min_cells_per_donor`, `fdr_cutoff`, number of
genes in the table and figure, colours) are set at the top of `pseudobulk_de.R`.

## CLI Reference

```bash
Rscript skills/pseudobulk-de/pseudobulk_de.R --input <data_dir> --output <out_dir>
```

| Flag | Required | Meaning |
|---|---|---|
| `--input` | yes | Directory holding `counts.tsv` and `cells.tsv`. |
| `--output` | yes | Directory to create for results. Must not exist yet. |

Paths are relative to the current working directory. Run from the repository root.

## Demo

From the repository root, using the six-donor example in `data/` (3 healthy, 3 disease,
200 cells each, 50 genes):

```bash
Rscript skills/pseudobulk-de/pseudobulk_de.R --input data --output results/run1
```

Running the same command again stops with "Output path already exists", so the first run's
results are not overwritten.

## Output Structure

```
<out_dir>/
├── de.tsv                          # gene, log2_fc, p_value, q_value; sorted by p_value
├── report.md                       # procedure, filters, model, contrast, top genes, figure
├── result.json                     # parameters, counts, n_significant (q < fdr_cutoff)
├── top_genes_donor_logcpm.pdf      # figure: donor-level log2 CPM of the top genes
├── top_genes_donor_logcpm.png      # same figure, embedded in report.md
├── top_genes_donor_logcpm.tsv      # source data of the figure
└── reproducibility/
    ├── commands.sh                 # exact command and working directory
    └── session_info.txt            # R and package versions
```

## Safety

- Read-only on inputs; writes only into a new `--output` directory and refuses an existing path.
- Uses no network and no patient identifiers beyond the donor IDs supplied.
- Statistical limits that the report states: with few donors per group, power is low and a
  non-significant gene is not evidence of no difference. All cells are pooled per donor, so shifts
  in cell-type composition appear as DE; run per cell type when annotations exist. With a small
  gene panel, TMM normalisation and the dispersion trend rest on few genes.
- Results are for research use, not clinical decisions.

## Integration with Bio Orchestrator

- **Routing:** the orchestrator sends requests that match `trigger_keywords` and supply a
  genes × cells count table with donor and condition labels.
- **Upstream:** a QC / cell-filtering skill, and a cell-type annotation skill if per-cell-type DE
  is wanted (subset the cells, then run once per cell type into separate output directories).
- **Downstream:** `de.tsv` feeds enrichment or pathway skills; `result.json` gives a
  machine-readable summary (`n_significant`, counts, parameters) for the orchestrator.
- **Provenance:** `reproducibility/commands.sh` and `session_info.txt` let the orchestrator rerun
  or audit a result.
