# pseudobulk-de

## Why This Exists

In multi-donor single-cell studies, condition (disease or healthy) is assigned to donors,
not cells. Testing cells as independent replicates ignores donor-to-donor variation and
produces many false positives. Summing counts per donor and testing those pseudobulk
samples with a bulk RNA-seq count model keeps the donor as the replication unit and
controls the false discovery rate (Squair et al. 2021; Crowell et al. 2020). This skill
runs that analysis in one command and writes a report a reviewer can audit.

## Core Capabilities

- Validates inputs: matching cell IDs, integer non-negative counts, one condition per
  donor, condition values `healthy`/`disease`, at least 2 donors per condition.
- Aggregates raw UMI counts to one pseudobulk sample per donor (sum over cells).
- Applies three logged filters: empty cells (0 UMIs), donors with < 10 cells, and
  low-expression genes (`edgeR::filterByExpr`).
- TMM normalization; edgeR quasi-likelihood negative binomial GLM, design `~ condition`,
  contrast disease - healthy.
- Benjamini-Hochberg q-values over all input genes.
- Report with data summary, filter table, model rationale, dispersion diagnostics,
  top-results table, MDS and volcano plots with captions, and a no-TMM sensitivity check.
- Refuses to write into an existing output directory.

## Input Formats

`--input` is a directory holding two tab-separated files:

| File | Layout |
|---|---|
| `counts.tsv` | Raw UMI counts, genes x cells. First column `gene` (unique IDs); every other column is one cell, headed by its cell ID. |
| `cells.tsv` | One row per cell: `cell_id` (matches the count column names), `donor_id`, `condition` (`healthy` or `disease`). Extra columns are ignored. |

Every cell must appear in both files. Counts must be raw integers, not normalized values.

## Workflow

1. Parse `--input` and `--output`; stop if `--output` already exists.
2. Read and validate both files; stop with a clear message on any mismatch.
3. Filter cells with zero total UMIs, then donors with fewer than 10 cells; require at
   least 2 donors per condition.
4. Sum counts per donor into a genes x donors pseudobulk matrix.
5. Filter genes with `filterByExpr(group = condition)`.
6. TMM-normalize, fit `glmQLFit(~ condition)` with `healthy` as reference, test the
   `conditiondisease` coefficient with `glmQLFTest`.
7. BH-adjust p-values over all input genes (filtered genes count as untested).
8. Write `de.tsv`, `result.json`, `report.md`, figures and reproducibility files.

## CLI Reference

```bash
Rscript skills/pseudobulk-de/pseudobulk_de.R --input <dir> --output <out_dir>
```

| Flag | Required | Meaning |
|---|---|---|
| `--input <dir>` | yes | Directory with `counts.tsv` and `cells.tsv`. |
| `--output <out_dir>` | yes | New directory for results. The script exits with an error if it exists. |
| `-h`, `--help` | no | Print usage. |

Fixed parameters (edit the constants at the top of the script to change them):
`MIN_CELLS_PER_DONOR = 10`, `MIN_DONORS_PER_CONDITION = 2`, `FDR_THRESHOLD = 0.05`.
Exit status is 0 on success and 1 on any validation error or refusal.

## Demo

Run on the example data set in `data/` (6 donors, 3 healthy and 3 disease, 200 cells
each, 50 genes) from the repository root:

```bash
Rscript skills/pseudobulk-de/pseudobulk_de.R --input data --output results/run1
```

Expected result: no cell, donor or gene is filtered; all 50 genes are tested; GENE33 is
the only gene at q < 0.05 (log2 FC about +2.0, higher in disease). Running the same
command again fails because `results/run1` already exists.

## Output Structure

```
<out_dir>/
├── de.tsv                       # gene, log2_fc, p_value, q_value; one row per input gene
├── report.md                    # procedure and results for a reviewer
├── result.json                  # parameters, counts, filter log, n_significant_q05
├── figures/
│   ├── mds.png                  # MDS of donor pseudobulk samples
│   └── volcano.png              # log2 FC vs -log10 p
└── reproducibility/
    ├── commands.sh              # exact command that produced the outputs
    └── sessionInfo.txt          # R and package versions
```

`log2_fc` is disease vs healthy (positive = higher in disease). Genes removed by the
expression filter keep their row with `NA` in `log2_fc`, `p_value` and `q_value`.

## Dependencies

- R >= 4.3
- CRAN: dplyr, readr, ggplot2, jsonlite
- Bioconductor: edgeR (>= 4.0, for `normLibSizes` and the current QL method), limma

## Safety

- Never overwrites: an existing `--output` path (file or directory) stops the run before
  anything is written.
- Read-only on inputs; writes only inside `--output`.
- Fails loudly instead of silently dropping data: unmatched cell IDs, non-integer counts,
  unknown conditions or a donor in two conditions stop the run.
- Statistical guardrails: donors are the replicates, so the run stops if fewer than 2 donors
  per condition remain. The report states the residual degrees of freedom and warns that
  extreme p-values from small donor counts reflect the model, not exact probabilities.
- The analysis assumes one cell type. Run it per cell type, because changes in cell-type
  composition would otherwise appear as differential expression.
- No network access; no data leaves the machine.

## Integration with Bio Orchestrator

Route here when the user asks for differential expression between conditions in
single-cell data with multiple donors or samples per condition (trigger keywords above).
The orchestrator should:

1. Provide a directory with `counts.tsv` and `cells.tsv` in the formats above. Upstream
   skills that produce an annotated count matrix should export per cell type.
2. Call the CLI with a fresh `--output` directory, for example one per cell type.
3. Read `result.json` for machine-readable results (`n_significant_q05`,
   `significant_genes`, `counts.filters`) and pass `de.tsv` downstream, for example to
   pathway enrichment. Show `report.md` to the user.
4. Treat a non-zero exit status as a failure and show the error message from stderr.
