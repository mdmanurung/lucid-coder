# pseudobulk-de

## Why This Exists

Single-cell DE tests that treat each cell as a replicate ignore that cells from one donor
are correlated, which inflates false positives by orders of magnitude (Squair et al. 2021).
The disease effect varies between donors, so the donor is the replication unit. This skill
aggregates cells to one pseudobulk sample per donor and runs a count model across donors.

## Core Capabilities

- Sums raw UMI counts per donor (genes x donors matrix).
- Filters cells with missing metadata, donors with too few cells, and low-expression genes
  (`edgeR::filterByExpr`), reporting what each filter removed.
- TMM normalisation, edgeR quasi-likelihood GLM `~ condition` (healthy reference), QL F-test.
- Benjamini-Hochberg q-values over all tested genes.
- Report with data summary, replication unit, filters, model rationale, contrast, testing
  family, top genes and a captioned volcano plot.
- Validates inputs and refuses to overwrite an existing output directory.

## Input Formats

`--input` is a directory containing:

| File | Layout |
| --- | --- |
| `counts.tsv` | Raw integer UMI counts, genes x cells. First column `gene`; every other column is one cell, headed by its cell ID. |
| `cells.tsv` | One row per cell: `cell_id` (matches count column names), `donor_id`, `condition` (`healthy` or `disease`). |

Each donor must belong to exactly one condition; at least 2 donors per condition are needed.
Input is treated as one cell population; for multiple cell types, run once per cell type.

## Workflow

1. Validate inputs (columns, unique IDs, non-negative integer counts, condition values).
2. Drop cells with no metadata row or missing `donor_id`/`condition`.
3. Drop donors with fewer than `--min-cells` cells.
4. Sum counts per donor into pseudobulk samples.
5. Drop genes failing `filterByExpr(group = condition)`.
6. TMM normalisation, `estimateDisp`, `glmQLFit(robust = TRUE)`, `glmQLFTest` on `conditiondisease`.
7. BH adjustment over tested genes; write outputs.

## CLI Reference

```bash
Rscript skills/pseudobulk-de/pseudobulk_de.R --input <dir> --output <new_dir> [--min-cells 10]
```

| Flag | Required | Meaning |
| --- | --- | --- |
| `--input` | yes | Directory with `counts.tsv` and `cells.tsv` |
| `--output` | yes | Output directory; must not exist (the script refuses to overwrite) |
| `--min-cells` | no | Minimum cells per donor to keep the donor (default 10) |

Exits non-zero with a message on any validation failure.

## Demo

```bash
Rscript skills/pseudobulk-de/pseudobulk_de.R --input data --output results/run1
```

On the bundled data (6 donors, 3 healthy / 3 disease, 1,200 cells, 50 genes) all filters
remove nothing; 50 genes are tested and 1 (GENE33, log2 FC about 2.0) is significant at q < 0.05.

## Output Structure

```
<out_dir>/
├── de.tsv                       # gene, log2_fc (disease vs healthy), p_value, q_value; every input gene
├── report.md                    # procedure and results for a reviewer
├── volcano.png                  # Figure 1 of the report
├── result.json                  # parameters, counts, n_significant_q05, software versions
└── reproducibility/
    └── commands.sh              # exact command that produced the outputs
```

Genes removed by the expression filter appear in `de.tsv` with `NA` statistics and are
outside the BH family.

## Dependencies

- R >= 4.3 (`Rscript`)
- Bioconductor: `edgeR` (>= 4.0, for `normLibSizes`), `limma`
- CRAN: `ggplot2`, `jsonlite`

## Safety

- Read-only on inputs; writes only inside a new `--output` directory and refuses an existing one.
- No network access, no data leaves the machine.
- Statistical, not clinical: results are research findings and need validation before any
  diagnostic use. With few donors per group, non-significant genes are not evidence of no effect.
- Donor and condition are fully nested, so donor-level batch aligned with condition cannot be
  separated from disease; composition shifts in mixed populations confound DE.

## Integration with Bio Orchestrator

Route here when a request mentions differential expression between conditions in single-cell
data with multiple donors (see `trigger_keywords`). Upstream: QC, clustering or cell-type
annotation skills, which should hand over raw counts for one cell population plus per-cell
donor/condition metadata. Downstream: `de.tsv` feeds enrichment or pathway skills; `result.json`
gives the orchestrator the significant-gene count without parsing the report.
