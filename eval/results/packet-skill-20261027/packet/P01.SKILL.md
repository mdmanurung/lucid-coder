# pseudobulk-de

## Why This Exists

Single-cell DE tests that treat each cell as a replicate confuse cell-to-cell variation with
variation between donors. P-values from those tests are badly anti-conservative
(pseudoreplication). The condition is assigned to donors, not cells, so the donor is the
replication unit. This skill sums each donor's cells into one pseudobulk profile and tests at
the donor level with edgeR, a well-calibrated approach in benchmarks (Squair et al. 2021;
Crowell et al. 2020).

## Core Capabilities

- Aggregates raw UMI counts to donor-level pseudobulk profiles (sum per gene per donor).
- Checks that cell metadata matches the count columns and that each donor has one condition.
- Drops donors with too few cells and genes failing `edgeR::filterByExpr`, and reports what
  each filter removed.
- TMM normalisation, then an edgeR quasi-likelihood GLM `~ condition` with `healthy` as the
  reference. Reports `log2_fc` (disease vs healthy), `p_value` and BH `q_value` per gene.
- Writes a reviewer-oriented `report.md` (data summary, replication unit, filters, model,
  contrast, multiple-testing family, top genes, a captioned per-donor figure, limitations),
  a machine-readable `result.json`, and the exact command for reproduction.

## Input Formats

`--input <dir>` must contain two tab-separated files:

| File | Layout | Columns |
| --- | --- | --- |
| `counts.tsv` | genes x cells, raw UMI counts (integers, not normalised) | `gene`, then one column per cell headed by its cell ID |
| `cells.tsv` | one row per cell | `cell_id` (matches the count column names), `donor_id`, `condition` (`healthy` or `disease`) |

Every count column needs a row in `cells.tsv`; extra metadata rows are ignored. A
`condition` other than `healthy`/`disease` stops the run.

## Workflow

1. Parse `--input` and `--output`. Refuse to run if the output path already exists.
2. Read counts and cell metadata, then align the metadata to the count columns by `cell_id`.
3. Sum raw counts per gene per donor to build a genes x donors pseudobulk matrix.
4. Filter donors with fewer than 10 cells, then genes failing `filterByExpr(group = condition)`.
5. Compute TMM normalisation factors.
6. Fit `glmQLFit(design = ~ condition, robust = TRUE)` and test coefficient
   `conditiondisease` with `glmQLFTest`.
7. Apply BH across all genes that passed the filter. Filtered genes stay in `de.tsv` as `NA`.
8. Write `de.tsv`, the figure and its source data, `result.json`, `report.md` and
   `reproducibility/`.

Tunable constants (reference level, colours, minimum cells per donor, FDR cutoff, top-N) sit
in the `# Parameters ----` block at the top of the script.

## CLI Reference

```bash
Rscript skills/pseudobulk-de/pseudobulk_de.R --input <input_dir> --output <out_dir>
```

| Flag | Required | Description |
| --- | --- | --- |
| `--input` | yes | Directory containing `counts.tsv` and `cells.tsv` |
| `--output` | yes | New directory for the results; the run stops if it already exists |

If either flag is missing, the script prints a usage line and exits non-zero.

## Demo

On the bundled example (6 donors, 3 healthy and 3 disease, 1200 cells, 50 genes):

```bash
Rscript skills/pseudobulk-de/pseudobulk_de.R --input data --output results/run1
```

Running the same command again fails with `Output 'results/run1' already exists`, so a
second run needs a new `--output`.

## Output Structure

```
<out_dir>/
├── de.tsv                    # gene, log2_fc (disease vs healthy), p_value, q_value; sorted by p_value
├── report.md                 # procedure and results for a reviewer
├── result.json               # parameters, counts, n_significant at q < 0.05
├── top_genes.png             # Figure 1: per-donor log2 CPM of the top genes
├── top_genes_source.tsv      # data plotted in Figure 1
└── reproducibility/
    ├── commands.sh           # exact command that produced this directory
    └── session_info.txt      # R and package versions
```

## Dependencies

Tested with R 4.5.2. Bioconductor: `edgeR` (tested 4.8.2; needs >= 4.0 for the QL method)
and `limma` (3.66.0, loaded by edgeR). CRAN: `dplyr`, `tidyr`, `readr`, `purrr`, `stringr`,
`forcats`, `ggplot2` (4.0.3), `jsonlite` (2.0.0). Arguments are parsed in base R, so no CLI
package is needed.

## Safety

- Never overwrites results: an existing `--output` path is refused before any work starts.
- Never writes to the input directory.
- Makes no network calls and sends no data anywhere.
- Stops on a mismatch between cell metadata and count columns, on a donor assigned to two
  conditions, or on an unknown condition label, rather than mislabelling cells.
- This is a statistical research tool, not a diagnostic. With 3 donors per group, power is
  low and results need confirmation in an independent cohort.

## Integration with Bio Orchestrator

Route here when a request asks which genes differ between conditions in single-cell or
single-nucleus RNA-seq with several donors per condition (see `trigger_keywords`). The
orchestrator should:

1. Provide a directory with `counts.tsv` and `cells.tsv` in the formats above, after any
   upstream QC or cell-type subsetting. For per-cell-type DE, call the skill once per subset,
   each with its own `--output`.
2. Pass a fresh `--output` directory for each call.
3. Read `result.json` for `n_significant` and the counts, and `de.tsv` for gene-level results
   to hand on to downstream enrichment or reporting skills. `report.md` is the human-facing
   summary.
